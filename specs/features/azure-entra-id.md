## Summary

Shipping hosting package **`Neox.Aspire.Hosting.Azure.EntraId`** under `src/hosting/Neox.Aspire.Hosting.Azure.EntraId/`. Namespace is `Neox.Aspire.Hosting.Azure`, matching [`azure-custom-domains`](azure-custom-domains.md).

The public hosting API is **`AddAzureAppRegistration`** (`AzureProvisioningResource` + `ConfigureInfrastructure` + `Azure.Provisioning.Compile()`), **`WithSupportedAccountType`** (Graph `signInAudience`), **`AddScope`** (child `AzureEntraIdScopeResource`; Graph `api.oauth2PermissionScopes`), **`AddAppRole`** (child `AzureEntraIdAppRoleResource`; Graph `appRoles` emitted only by the parent module), **`AddWebApplication`** (child `AzureEntraIdWebApplicationResource`; Graph `web.redirectUris` emitted only by the parent module), **`AddSpaApplication`** (child `AzureEntraIdSpaApplicationResource`; Graph `spa.redirectUris` emitted only by the parent module), **`WithPermission`** (in-model Graph `requiredResourceAccess` + Aspire `WaitFor` the exposer app registration), **`AddCertificate`** (top-level `AsymmetricX509CertResource` that verifies a cert in the platform X.509 store), **`WithKeyCredential`** (Graph `keyCredentials` + `WaitFor` the cert), **`WithSecret`** (creates an **Entra ID password credential resource** that `WaitFor`s the registration then Graph `addPassword` into a secret `ParameterResource` + AppHost user secrets), **`EntraIdInstance`** (`Workforce` or `Ciam` tenant subdomain), **`WithMicrosoftIdentityWebApplication`** (env injection for Microsoft.Identity.Web on an `IResourceWithEnvironment`; first argument `EntraIdInstance`), and **`WithEntraIdSpaApplication`** (env injection `ENTRA_*` for a SPA; first argument `EntraIdInstance`). Graph constructs (`GraphApplication`, `GraphServicePrincipal`, `GraphWebApplication`, `GraphSpaApplication`, `GraphApiApplication`, `GraphPermissionScope`, `GraphAppRole`, `GraphRequiredResourceAccess`, `GraphResourceAccess`, `GraphKeyCredential`, …) come from Shipping CDK [`Neox.Azure.Provisioning.Graph`](azure-provisioning-graph.md) (source-generated from official msgraph-bicep-types JSON). Existing apps use Aspire 13.4.6 `AsExisting` / `RunAsExisting` / `PublishAsExisting` (Graph `uniqueName`; resource group omitted). The sample AppHost under `tests/azure-entraid/` wires an **Auth** group.

## User scenarios

1. **Consumer packs locally** — Arcade pack emits `Neox.Aspire.Hosting.Azure.EntraId` under Shipping.
2. **AppHost author creates an app registration** — `builder.AddAzureAppRegistration("web")` registers an `AzureProvisioningResource`; `aspire run` / `aspire deploy` compiles Graph Bicep (plus `bicepconfig.json` beside the module) and ARM deploys it; outputs `clientId` and `objectId` are available via `GetOutput`.
3. **AppHost author binds an existing app** — `RunAsExisting` / `PublishAsExisting` / `AsExisting` emit Bicep `existing` on `Microsoft.Graph/applications` (no create SKU/displayName on that resource).
4. **AppHost author sets supported account types** — `app.WithSupportedAccountType(SupportedAccountType.AzureADMultipleOrgs)` writes Graph `signInAudience` on the create path. Default is `AzureADMyOrg` when the method is not called. `AzureADandPersonalMicrosoftAccount` and `PersonalMicrosoftAccount` also write `api.requestedAccessTokenVersion: 2` on create (even without scopes). `.ConfigureInfrastructure` can still mutate typed constructs from `Neox.Azure.Provisioning.Graph` before `Compile()`.
5. **AppHost author exposes OAuth2 scopes** — `app.AddScope(name, value, adminConsentDisplayName, adminConsentDescription)` (optional user-consent overload) registers an `AzureEntraIdScopeResource` child (`IResourceWithParent<AzureEntraIdAppRegistrationResource>`). The parent’s `ConfigureInfrastructure` writes `api.oauth2PermissionScopes` into the same Graph application module (create path). The scope resource is not an `AzureProvisioningResource` and has no Bicep module.
6. **AppHost author exposes app roles** — `app.AddAppRole(name, allowedMemberTypes, value, displayName, description)` registers an `AzureEntraIdAppRoleResource` child (`IResourceWithParent<AzureEntraIdAppRegistrationResource>`). `AllowedMemberTypes` is a `[Flags]` enum (`User`, `Application`, or both). The parent’s `ConfigureInfrastructure` writes `appRoles` into the same Graph application module (create path). The app-role resource is not an `AzureProvisioningResource` and has no Bicep module.
7. **AppHost author consumes an in-model permission** — `consumer.WithPermission(scopeOrRole)` where `scopeOrRole` is `IResourceBuilder<TAzureEntraIdPermissibleResource>` (`TAzureEntraIdPermissibleResource : IAzureEntraIdPermissibleResource`). The consumer’s `ConfigureInfrastructure` writes Graph `requiredResourceAccess` (create path) grouped by exposer; `resourceAppId` is the exposer’s `ClientId` output. The consumer `WaitFor`s the exposer app registration (not the child). Self-permission skips `WaitFor`.
8. **AppHost author attaches a store certificate** — `builder.AddCertificate(name, thumbprint, storeLocation)` where `thumbprint` is `IResourceBuilder<ParameterResource>` (typically `secret: true`) registers an `AsymmetricX509CertResource` that looks up `StoreName.My` at `StoreLocation.CurrentUser` or `LocalMachine`. The parameter is resolved at initialize time (not at `Configure()`). `app.WithKeyCredential(cert)` emits Graph `keyCredentials` (create path) and `WaitFor`s the cert resource. The public CER bytes are a deferred secure Bicep parameter evaluated after the store check succeeds.
9. **Contributor runs the harness** — `tests/azure-entraid/aspire/apphost` starts Auth (`neox-entra-auth-api`) then the stub Web API (Microsoft.Identity.Web + Swagger OAuth2 implicit; env via `WithMicrosoftIdentityWebApplication(EntraIdInstance.Workforce, …)`) and Vite React SPA (MSAL popup; env via `WithEntraIdSpaApplication(EntraIdInstance.Workforce, …)`). Sample SPA registration `WithPermission`s the API `access_as_user` scope and `AddSpaApplication`s a child with `WithRedirectUri(http://localhost/)` (no port). Sample `Auth.cs` `AddCertificate`s `ServiceNames.Auth.ApiCert` (`neox-entra-auth-api-cert`) from `StoreName.My` at `StoreLocation.CurrentUser` using secret parameter `{ApiCert}-thumbprint` (`Parameters:neox-entra-auth-api-cert-thumbprint`) and `WithKeyCredential`s it on the API registration, and `WithSecret`s `ServiceNames.Auth.ApiClientSecret` (`Parameters:neox-entra-auth-api-client-secret`). The API registration `AddWebApplication`s a swagger child with `WithRedirectUri(https://localhost/swagger/oauth2-redirect.html)` (no port).
10. **Contributor runs unit tests** — in-process `CreateBuilder` asserts generated Bicep and `bicepconfig.json`; no live Azure or Graph. SPA Vitest under `tests/azure-entraid/src/spa` asserts `ENTRA_*` → `msalConfig` / `loginRequest`.
11. **AppHost author models a web platform** — `app.AddWebApplication(name)` registers an `AzureEntraIdWebApplicationResource` child (`IResourceWithParent<AzureEntraIdAppRegistrationResource>`). `webApp.WithRedirectUri(uri)` accumulates Graph `web.redirectUris`. The parent’s `ConfigureInfrastructure` writes the merged URI list into the same Graph application module (create path). The web-application resource is not an `AzureProvisioningResource` and has no Bicep module.
12. **AppHost author wires Microsoft.Identity.Web** — `project.WithMicrosoftIdentityWebApplication(EntraIdInstance.Workforce, webApp, sectionName: "AzureAd__")` (or `EntraIdInstance.Ciam(subdomain)`) injects `AzureAd__*` environment variables (`Instance` from **Entra ID instance**, `TenantId` from AppHost `Azure:TenantId`, `ClientId` from the parent registration, optional `Audience` / `ClientCredentials` / `ClientSecret`) and `WaitFor`s the parent (key-credential certs and **Entra ID password credential** resources).
13. **AppHost author models a SPA platform** — `app.AddSpaApplication(name)` registers an `AzureEntraIdSpaApplicationResource` child (`IResourceWithParent<AzureEntraIdAppRegistrationResource>`). `spaApp.WithRedirectUri(uri)` accumulates Graph `spa.redirectUris`. The parent’s `ConfigureInfrastructure` writes the URI list into the same Graph application module (create path). The SPA-application resource is not an `AzureProvisioningResource` and has no Bicep module.
14. **AppHost author wires a SPA** — `vite.WithEntraIdSpaApplication(EntraIdInstance.Workforce, spaApp, sectionName: "ENTRA_")` (or `EntraIdInstance.Ciam(subdomain)`) injects `ENTRA_*` environment variables (`Instance` from **Entra ID instance**, `TenantId` from AppHost `Azure:TenantId`, `ClientId` from the parent registration, `LoginScopes` `openid offline_access`, optional `Audience` / `Scope` / `ClientSecret`) and `WaitFor`s the parent (and parent **Entra ID password credential** resources when present).
15. **AppHost author creates a client secret** — `var secret = builder.AddParameter("api-client-secret", secret: true)` then `app.WithSecret(secret)` creates an **Entra ID password credential resource** child (`IResourceWithParent`). After the parent reaches `Running`, run-mode initialize calls Graph `addPassword`, fills the parameter, and persists `Parameters:{name}` to AppHost user secrets when missing. Re-runs reuse an existing config/user-secret value. Consumers via `WithMicrosoftIdentityWebApplication` / `WithEntraIdSpaApplication` receive `{sectionName}ClientSecret` and `WaitFor` the password credential resource.

## Business rules

1. **One Shipping Entra hosting package** — `Neox.Aspire.Hosting.Azure.EntraId` is the packable hosting id. Graph CDK types live in [`azure-provisioning-graph`](azure-provisioning-graph.md).
2. **Aspire Azure provisioning resource** — `AddAzureAppRegistration` subclasses `AzureProvisioningResource` and uses `AddAzureProvisioning` / `BicepProvisioner`. Infrastructure callbacks use Azure.Provisioning Graph constructs only (no Microsoft.Graph package; module is **not** assembled with a `StringBuilder`). Hand-written `GraphApplication` / `GraphServicePrincipal` / `GraphWebApplication` files are not kept in this package. **Run-mode exception:** the **Entra ID password credential resource** may call Microsoft Graph REST `addPassword` (`Azure.Identity` + HTTP) after the registration is ready — never as Bicep `passwordCredentials`.
3. **Azure.Provisioning Graph constructs** — infrastructure uses `GraphApplication` and `GraphServicePrincipal` from `Neox.Azure.Provisioning.Graph`. `ClientId` / `ObjectId` are `BicepOutputReference` backed by `ProvisioningOutput` (same pattern as Key Vault `VaultUri`).
4. **Post-compile Graph extension** — Aspire 13.4.6 `Compile()` / `BicepProvisioner` do not emit `extension microsoftGraphV1` or copy `bicepconfig.json`. `GetBicepTemplateFile` writes `bicepconfig.json` next to the module (types pin **1.0.0**, matching the Graph CDK snapshot) and **prefixes** `extension microsoftGraphV1` when missing. That prefix is the only remaining string patch of the template.
5. **Existing uses stock Aspire 13.4.6 APIs** — `AsExisting` / `RunAsExisting` / `PublishAsExisting`; annotation name is the Graph **`uniqueName`**, not ARM `name`. Use `CreateExistingOrNewProvisionableResource` + `GraphApplication.FromExisting` with `UniqueName` set from the annotation. **Do not** call `TryApplyExistingResourceAnnotation` (it assigns ARM `name`). `AsExistingInTenant` is not available on this Aspire version. Resource group on the annotation is omitted (Graph resources are tenant objects; ARM resource-group deployment is only the vehicle). Graph Bicep must emit `uniqueName:` and must not emit ARM `name:`.
6. **Default parameters** — `uniqueName` and `displayName` default to the Aspire resource name. `WithDisplayName` / `WithRedirectUri` / `WithIdentifierUri` / child `AddWebApplication` + `WithRedirectUri(Uri)` / child `AddSpaApplication` + `WithRedirectUri(Uri)` feed `Parameters` consumed by the infrastructure callback (`AsProvisioningParameter` / matching `ProvisioningParameter` identifiers: `displayName`, `redirectUris`, `spaRedirectUris`, `identifierUris`). `WithSupportedAccountType` is not a Bicep parameter: it sets Graph `signInAudience` as a module literal (`AzureADMyOrg` when omitted). `SupportedAccountType` members match Graph values (`AzureADMyOrg`, `AzureADMultipleOrgs`, `AzureADandPersonalMicrosoftAccount`, `PersonalMicrosoftAccount`); an undefined enum value throws. `AzureADandPersonalMicrosoftAccount` and `PersonalMicrosoftAccount` also emit `api.requestedAccessTokenVersion: 2` on the create Graph application (Graph rejects changing to those audiences without it). `WithDefaultIdentifierUri` cannot set `identifierUris: ['api://${app.appId}']` on the create resource (Bicep BCP079 self-reference). The same module emits a second Graph application (`appIdentifierUris`) with the same `uniqueName`, `signInAudience`, `identifierUris: ['api://${app.appId}']`, and `api.requestedAccessTokenVersion: 2` (Graph upsert; still one ARM deployment). Graph allows only `1`, `2`, or null for that property; omitting it on the identifier-URI PATCH is sent as `0` and fails. Create path also emits a service principal (`AppId = app.AppId`). Existing path uses Bicep `existing` (no `displayName` / `signInAudience` / `identifierUris` / `oauth2PermissionScopes` / `appRoles` / `requiredResourceAccess` / `keyCredentials` / `web` / `spa` on the application resource).
7. **OAuth2 scopes** — `AddScope` on `IResourceBuilder<AzureEntraIdAppRegistrationResource>` returns `IResourceBuilder<AzureEntraIdScopeResource>`. `AzureEntraIdScopeResource` implements `IResourceWithParent<AzureEntraIdAppRegistrationResource>` and **`IAzureEntraIdPermissibleResource`** (`Type` = `Scope`). It is not an `AzureProvisioningResource`. Duplicate Graph `value` on the same parent throws. Four-argument overload sets Graph `type` to `Admin` (no user-consent fields); six-argument overload sets `type` to `User` and emits user-consent display name/description. Graph `id` is a stable `Guid.CreateVersion5` from `{parent.Name}:{value}` (public on the resource as `Id`). `isEnabled` is `true`. Only the parent `ConfigureGraphInfrastructure` (create path) writes `GraphApplication.Api.Oauth2PermissionScopes` with `requestedAccessTokenVersion: 2`; existing path omits them.
8. **App roles** — `AddAppRole` on `IResourceBuilder<AzureEntraIdAppRegistrationResource>` returns `IResourceBuilder<AzureEntraIdAppRoleResource>`. Signature is `AddAppRole(name, allowedMemberTypes, value, displayName, description)`. `AzureEntraIdAppRoleResource` implements `IResourceWithParent<AzureEntraIdAppRegistrationResource>` and **`IAzureEntraIdPermissibleResource`** (`Type` = `Role`). It is not an `AzureProvisioningResource`. `AllowedMemberTypes` is a `[Flags]` enum (`User` = 1, `Application` = 2); Graph `allowedMemberTypes` is `'User'` and/or `'Application'`. A zero flags value throws. Duplicate Graph `value` on the same parent throws. Graph `id` is a stable UUID v5 from `{parent.Name}:{value}` with a namespace distinct from scopes (public on the resource as `Id`). `isEnabled` is `true`. Graph `origin` is omitted (read-only). Only the parent `ConfigureGraphInfrastructure` (create path) writes `GraphApplication.AppRoles`; existing path omits them.
9. **API permissions (`WithPermission`)** — `WithPermission<TAzureEntraIdPermissibleResource>(IResourceBuilder<TAzureEntraIdPermissibleResource>)` where `TAzureEntraIdPermissibleResource : IAzureEntraIdPermissibleResource`. No overload taking the bare resource. Accumulates; groups by exposer parent into Graph `requiredResourceAccess` (one object per API, several `resourceAccess`). Graph `resourceAccess[].type` is `'Scope'` or `'Role'`; `id` is the permissible resource’s `Id`. `resourceAppId` is the exposer’s `ClientId` (`app.appId`) as a Bicep parameter (`BicepOutputReference`) — that wires provision `DependsOn`. Self-permission (same app registration) uses `created.AppId` in-module and does not `WaitFor`. Otherwise the consumer `WaitFor`s the **exposer app registration** once per unique parent (`CreateResourceBuilder(parent)`). Duplicate `Id` on the same consumer throws. Only the consumer `ConfigureGraphInfrastructure` (create path) writes `GraphApplication.RequiredResourceAccess`; existing path omits them. Well-known first-party Graph permissions are out of scope.
10. **Store certificate (`AddCertificate`)** — `AddCertificate(name, thumbprint, storeLocation)` on `IDistributedApplicationBuilder` returns `IResourceBuilder<AsymmetricX509CertResource>`. `thumbprint` is `IResourceBuilder<ParameterResource>`; there is no string overload. The resource is not an `AzureProvisioningResource` and is not a child of the app registration. At initialize it resolves the parameter, opens `StoreName.My` at `StoreLocation.CurrentUser` or `LocalMachine`, finds the thumbprint (`X509FindType.FindByThumbprint`, `validOnly: false`), and publishes `Running` or `FailedToStart` (empty parameter, unresolved parameter, or missing cert). Lifecycle is TalkingClock: `ExcludeFromManifest`, initial state `NotStarted`, `OnInitializeResource` + `PublishUpdateAsync`. Its only role is the store check; it does not create or upload the certificate.
11. **Key credentials (`WithKeyCredential`)** — `WithKeyCredential(IResourceBuilder<AsymmetricX509CertResource>)` on `IResourceBuilder<AzureEntraIdAppRegistrationResource>`. Accumulates; duplicate cert instance or the same `ThumbprintParameter` on the same registration throws. Does not read `Parameter.Value` at `Configure()`. The registration `WaitFor`s the cert once. A deferred secure Bicep parameter (`keyCredential_{certName}`) is evaluated after WaitFor and holds public CER bytes (`X509ContentType.Cert` Base64). Create path writes `GraphApplication.KeyCredentials` (`type: AsymmetricX509Cert`, `usage: Verify`, `displayName` = Aspire cert resource name, `key` = parameter). Graph `keyCredentials` is replace-all: every `WithKeyCredential` on the model is emitted together. Existing path omits `keyCredentials`. Client secrets use **`WithSecret`** (not Bicep `passwordCredentials`).
12. **Client secrets (`WithSecret` / password credential resource)** — `WithSecret(IResourceBuilder<ParameterResource>)` on `IResourceBuilder<AzureEntraIdAppRegistrationResource>` returns the app registration builder (fluent like `WithKeyCredential`). The parameter must be `secret: true` (non-secret throws). Creates an **`EntraIdPasswordCredentialResource`** child that implements `IResourceWithParent<AzureEntraIdAppRegistrationResource>` (Aspire name `{parent.Name}-{parameter.Name}`), accumulates on `PasswordCredentials`, duplicate same `ParameterResource` on the same registration throws. Does **not** emit Bicep `passwordCredentials`. The password credential resource is `ExcludeFromManifest`, initial `NotStarted`. It does **not** use Aspire `WaitFor` on the parent (forbidden for `IResourceWithParent`); run-mode `OnInitializeResource` waits for the parent via `ResourceNotificationService.WaitForResourceAsync(parent.Name, Running)`, then: if AppHost configuration already has `Parameters:{name}`, skip Graph and complete the parameter; otherwise resolve parent `ObjectId`, call Graph REST `POST /v1.0/applications/{objectId}/addPassword` with `passwordCredential.displayName` = parameter name, complete `WaitForValueTcs`, persist via `IUserSecretsManager.TrySetSecret` when available, publish `Running` or `FailedToStart`. Deferred empty `ParameterDefault` avoids interactive prompt before initialize. Works for create and existing parents. Publish / Key Vault secret outputs are out of scope.
13. **Web applications (`AddWebApplication`)** — `AddWebApplication(name)` on `IResourceBuilder<AzureEntraIdAppRegistrationResource>` returns `IResourceBuilder<AzureEntraIdWebApplicationResource>`. `AzureEntraIdWebApplicationResource` implements `IResourceWithParent<AzureEntraIdAppRegistrationResource>`. It is not an `AzureProvisioningResource`. `WithRedirectUri(Uri)` on the child accumulates; the parent merges unique AbsoluteUris from the existing parent `WithRedirectUri(string)` annotation and every child’s URIs into `RedirectUrisParameter`. Duplicate Aspire resource `name` fails at `AddResource`. When at least one web redirect URI is present, create-path Bicep sets Graph `web.implicitGrantSettings` (`enableAccessTokenIssuance` and `enableIdTokenIssuance` true) for Swagger OAuth2 implicit. Only the parent `ConfigureGraphInfrastructure` (create path) writes `GraphApplication.Web`; existing path omits `web`.
14. **Microsoft.Identity.Web env (`WithMicrosoftIdentityWebApplication`)** — `WithMicrosoftIdentityWebApplication<TResource>(EntraIdInstance instance, IResourceBuilder<AzureEntraIdWebApplicationResource> webApplication, string sectionName = "AzureAd__")` where `TResource : IResourceWithEnvironment, IResourceWithWaitSupport`. First argument is required (**Entra ID instance**); there is no workforce-default overload. The hosting package does **not** reference `Microsoft.Identity.Web`. Injects `{sectionName}Instance` from the instance (`https://login.microsoftonline.com/` or `https://{subdomain}.ciamlogin.com/`), `{sectionName}TenantId` from AppHost configuration `Azure:TenantId` (omitted when absent), `{sectionName}ClientId` from the parent `ClientId` output, `{sectionName}Audience` as `api://{clientId}` when the parent has `WithDefaultIdentifierUri`, `{sectionName}ClientCredentials__{i}__*` (`SourceType` = `StoreWithThumbprint`, …) for each parent key credential, `{sectionName}ClientSecret` from the first parent **Entra ID password credential** parameter when any exist, and further password credentials as `ClientCredentials__{KeyCredentials.Count + i}__` (`SourceType` = `ClientSecret`, `ClientSecret` = parameter). `Ciam(IResourceBuilder<ParameterResource>)` does not read `Parameter.Value` at `Configure()`. The consumer `WaitFor`s the parent app registration, each key-credential cert, and each password credential resource. There is no generic `WithAuth` helper.
15. **SPA applications (`AddSpaApplication`)** — `AddSpaApplication(name)` on `IResourceBuilder<AzureEntraIdAppRegistrationResource>` returns `IResourceBuilder<AzureEntraIdSpaApplicationResource>`. `AzureEntraIdSpaApplicationResource` implements `IResourceWithParent<AzureEntraIdAppRegistrationResource>`. It is not an `AzureProvisioningResource`. `WithRedirectUri(Uri)` on the child accumulates; the parent merges unique AbsoluteUris from every SPA child’s URIs into `SpaRedirectUrisParameter` (`spaRedirectUris`). Duplicate Aspire resource `name` fails at `AddResource`. Create-path Bicep writes `GraphApplication.Spa` (`spa.redirectUris`) only when at least one SPA redirect URI is present. No implicit grant (public client, auth code + PKCE). Existing path omits `spa`.
16. **SPA env (`WithEntraIdSpaApplication`)** — `WithEntraIdSpaApplication<TResource>(EntraIdInstance instance, IResourceBuilder<AzureEntraIdSpaApplicationResource> spaApplication, string sectionName = "ENTRA_")` where `TResource : IResourceWithEnvironment, IResourceWithWaitSupport`. First argument is required (**Entra ID instance**); there is no workforce-default overload. The hosting package does **not** reference MSAL. Injects `{sectionName}Instance` from the instance (`https://login.microsoftonline.com/` or `https://{subdomain}.ciamlogin.com/`), `{sectionName}TenantId` from AppHost configuration `Azure:TenantId` (omitted when absent), `{sectionName}ClientId` from the parent `ClientId` output, `{sectionName}Audience` as `api://{clientId}` when the parent has `WithDefaultIdentifierUri`, `{sectionName}LoginScopes` as `openid offline_access` (interactive MSAL login; not API resource scopes), `{sectionName}Scope` as `api://{exposer.ClientId}/{value}` for the first in-model Scope **API permission** on the parent (omitted when none), and when the parent has **Entra ID password credential** resources the same `{sectionName}ClientSecret` / additional `ClientCredentials__*` pattern as Microsoft.Identity.Web. `Ciam(IResourceBuilder<ParameterResource>)` does not read `Parameter.Value` at `Configure()`. The consumer `WaitFor`s the parent app registration and each parent password credential resource (not key-credential certs).
17. **Outputs** — `clientId` (`app.appId`) and `objectId` (`app.id`). Prefer `WithMicrosoftIdentityWebApplication` for Microsoft.Identity.Web and `WithEntraIdSpaApplication` for a public-client SPA; consumers may still wire env with `GetOutput` / `WithEnvironment` (including `WithSecret` parameters).
18. **Deployer permissions** — Azure RG Contributor is not sufficient; the deploying identity needs Microsoft Graph `Application.ReadWrite.All` (and standard Aspire `Azure:SubscriptionId`, `Azure:Location`, `Azure:ResourceGroup`). The same Graph permission covers run-mode `WithSecret` `addPassword`.
19. **Sample AppHost layout** — `tests/azure-entraid/aspire/{apphost,service-defaults}` and `tests/azure-entraid/src/{apis,spa}` per `.cursor/rules/aspire-apphost.mdc`. Group order: Auth → Services → Web. SPA is a Vite folder; Aspire wires `AddViteApp` on the folder (no `.esproj`, no slnx project). Isolation: harness is not the Events AppHost and not the saas **test AppHost**. Sample `Auth.cs` exposes an API scope/role, `AddCertificate`s `ServiceNames.Auth.ApiCert` from `CurrentUser\My` with secret parameter `{ApiCert}-thumbprint`, `WithKeyCredential`s it on the API registration, `WithSecret`s `ServiceNames.Auth.ApiClientSecret` (`Parameters:neox-entra-auth-api-client-secret`), `AddWebApplication`s a swagger child with `WithRedirectUri(https://localhost/swagger/oauth2-redirect.html)` (no port), and the SPA registration `WithPermission`s the `access_as_user` scope and `AddSpaApplication`s a child (`ServiceNames.Auth.SpaApp`) with `WithRedirectUri(http://localhost/)` (no port). Sample API uses Microsoft.Identity.Web (`AddMicrosoftIdentityWebApi`) and Swagger OAuth2 implicit (no Graph SDK, no SQL token cache; API auth remains certificate-based via `WithMicrosoftIdentityWebApplication`). Sample `Services.cs` calls `WithMicrosoftIdentityWebApplication(EntraIdInstance.Workforce, …)` on the API project. Sample `Web.cs` calls `WithEntraIdSpaApplication(EntraIdInstance.Workforce, …)` on the Vite app. Sample SPA uses `@azure/msal-react` (`MsalAuthenticationTemplate` popup) and Vite `envPrefix` `ENTRA_`.
20. **Tests** — xUnit in-process under `tests/azure-entraid/`; no live ARM / Graph / `az deployment`. Existing asserts remain (`uniqueName:`, no `displayName:` on the existing path). Resource type is `AzureEntraIdAppRegistrationResource` (`AzureProvisioningResource`). Scope, app-role, web-application, SPA-application, `requiredResourceAccess`, and `keyCredentials` Bicep is asserted via the **parent** `GetBicepTemplateString()`. `WithSecret` asserts password credential child (`IResourceWithParent`), duplicate / non-secret throw, and that Bicep never emits `passwordCredentials`; lifecycle tests use a fake Graph `addPassword` seam on the credential resource (no live Graph). `WaitAnnotation` on the consumer points at the exposer; `WaitAnnotation` on a registration with `WithKeyCredential` points at the cert resource; password credentials do **not** carry a `WaitAnnotation` on the parent (parent readiness is via `ResourceNotificationService`); `WaitAnnotation` on a project with `WithMicrosoftIdentityWebApplication` points at the parent registration, certs, and password credentials; `WaitAnnotation` on a Vite app with `WithEntraIdSpaApplication` points at the parent registration and password credentials (not certs). Workforce env tests assert `{sectionName}Instance` is `https://login.microsoftonline.com/`; CIAM string tests assert `https://{subdomain}.ciamlogin.com/`; `Ciam("")` and scheme/slash subdomains throw. SPA Vitest under `tests/azure-entraid/src/spa` asserts `ENTRA_*` mapping into `msalConfig` / `loginRequest`.
21. **Entra ID instance (`EntraIdInstance`)** — public sealed type. `Workforce` is `https://login.microsoftonline.com/`. `Ciam(string tenantSubdomain)` trims, rejects null/whitespace, `://`, and `/`, and yields `https://{subdomain}.ciamlogin.com/`. `Ciam(IResourceBuilder<ParameterResource> tenantSubdomain)` interpolates the parameter into that URL at env-callback time (does not read `Parameter.Value` at `Configure()`). A null instance argument on the env helpers throws.
